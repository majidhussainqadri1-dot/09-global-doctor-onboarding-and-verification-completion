# File 09 1.2.0 Staging Acceptance

This checklist must be executed on Hostinger-equivalent staging with representative roles and no real identity documents.

1. Verify exact package checksum, one canonical top-level folder, manifest and SBOM.
2. Test fresh install, 1.1.x upgrade, concurrent activation lock, deactivation/reactivation and non-destructive uninstall.
3. Verify File 00/File 02 contracts, suspended/minor/duplicate/unknown dependency fail-closed behavior.
4. Complete applicant eligibility, five-step wizard, autosave/cross-device conflict, draft expiry, upload, completeness, submit, more-info/resubmit and withdrawal.
5. Verify private storage direct-web denial, key rotation/recovery, malware/polyglot/PDF/image attacks, quotas/rates and no metadata leakage.
6. Test reviewer assignment, conflict/self-review, step-up, one-time evidence access, structured findings, recommendation/finalizer separation and quality sampling.
7. Test verified/rejected, File 00 signed claim acknowledgment, public projection, renewal/grace/expiry, suspension/revocation, appeal and reinstatement.
8. Test File 19 events, retries/dead letters/replay and File 03/07/08/CF-01 consumers.
9. Test export, correction workflow, consent withdrawal, erasure, legal hold, orphan cleanup and guarded uninstall.
10. Test 320–1920px, 400% zoom, keyboard, screen reader, focus, contrast, reduced motion, English (US), Urdu/Arabic RTL and time-zone/date correctness.
11. Execute provider outage, DB/cache/cron delay, Safe Mode, repair, backup restore and rollback drills.
12. Record two fresh staging reviews, all fixes/retests, zero known unresolved critical/high defects and explicit Founder acceptance.

Passing source/CI/package checks does not satisfy this external staging gate.
